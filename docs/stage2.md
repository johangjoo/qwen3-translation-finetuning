# 2단계: 연구용 저장소의 뼈대 만들기

2단계의 목적은 대학원 지원 포트폴리오를 보는 사람이 **데이터 준비 → 모델 학습 → 번역 비교 → 결과 분석**을 따라갈 수 있게 정리하는 것입니다.

## 2-1. 폴더 구조

`configs`, `data`, `scripts`, `evaluation`, `assets`를 만들고 README와 의존성 목록을 작성하는 단계입니다. 이번 이전에서 생성했습니다. 추가로 원본 근거를 보존하는 `archive`, 설명을 담는 `docs`, 검증용 `tests`도 만들었습니다.

## 2-2. 각 폴더의 역할

| 폴더 | 쉬운 설명 | 현재 상태 |
|---|---|---|
| configs | 모델을 어떤 조건으로 학습시키는지 적은 설정표 | 8B/14B 원본 코드에서 추출 완료 |
| data | 어떤 데이터를 어떤 형식으로 넣는지 설명하는 곳 | 직접 작성한 예제와 전처리 설명 추가; 실데이터 미포함 |
| scripts | 데이터 준비·학습·추론을 실제로 수행하는 코드 | 원본에서 선별·통합 완료 |
| evaluation | 학습 전후 번역을 같은 조건으로 비교하는 곳 | 비교 코드·기록 양식 준비; 실제 결과는 미등록 |
| assets | 보고서 그림·비교 스크린샷을 모으는 곳 | 자료를 찾은 뒤 추가할 위치만 준비 |

예를 들어 `configs/qwen3_8b_lora.yaml`을 보면 학습률과 batch를 알 수 있고, `scripts/train.py`를 보면 그 설정으로 모델을 학습시키는 과정을 알 수 있습니다. `evaluation/8b_base_vs_lora.md`에는 실제 비교 결과와 관찰을 적습니다.

## 2-3. GitHub에 반영

로컬에서 파일을 정리하고 검사한 뒤 commit/push하는 단계입니다. 원본 `Translate-Project`에는 변경을 가하지 않고 새 저장소에 필요한 내용만 옮깁니다.

이번 작업은 2단계 구조 생성에 더해, 다음 단계였던 **기존 코드 선별·이전**까지 포함합니다. 다만 파일을 채운 것과 실험 결과가 완성된 것은 구분해야 합니다.

## 다음에 채울 것

1. 예전 보고서와 실제 8B/14B 비교 화면·번역 출력 확보
2. 데이터셋 이름·규모·분리 방식과 최종 실행 설정을 로그로 확인
3. 정성 비교표에 성공·실패 사례와 한계 작성
4. 자료가 충분해지면 별도 평가 데이터로 정량 비교 진행

모든 설정을 새로 최적화하거나 재학습해야 2단계가 끝나는 것은 아닙니다. 지금은 실제 작업의 구조와 근거를 읽기 좋게 모으는 단계입니다.
